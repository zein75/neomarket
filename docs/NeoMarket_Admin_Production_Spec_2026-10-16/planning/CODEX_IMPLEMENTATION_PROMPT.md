# Ready-to-use prompt for Codex (run at `market/` repository root)

Используй `$neomarket-exhaustive-qa` и `AGENTS.md`. Главный источник требований — `NeoMarket_Admin_Production_Spec_2026-10-16/MASTER_SPEC.md` и остальные документы этого комплекта. Старые каноны и OpenAPI не являются источниками истины. Stitch `docs/design-system/stitch/admin-panel/reference.png` / `source-official.html` — обязательный визуальный эталон.

**Цель:** самостоятельно полностью реализовать Admin Panel NeoMarket как настоящую административную систему маркетплейса: безопасный OIDC/MFA BFF, roles+permissions, модерация версии товара и каждого поля/SKU, безопасный claim+heartbeat+release, idempotent approve/reject с B2B ack, управление деревом категорий, атрибутами/брендами, проверка продавцов, жалобы и апелляции, причины отклонений, массовые операции, аудит, monitoring. Все рабочие показатели и товары — реальные данные B2B/Admin/B2C, без демонстрационных заглушек.

Начни с ревизии файлов из `audit/CURRENT_STATE.md` и P0 реестра. Прежде всего исправь реально подтверждённую проблему `decide_ticket`: `claim_token`, `product_revision`, idempotency key принимаются, но не проверяются должным образом. Для этого создай строгую модель ревизий и lease с fencing, server-side compare-and-swap, тесты на конкуренцию и поздние ответы. Не открывай настоящую модерацию, пока реальный OIDC/MFA и RBAC не проверены.

Для категорий B2B остаётся владельцем истины, Admin использует безопасные служебные команды и acknowledgements. Запрещено прямое изменение БД B2B из Admin, удаление категории со связанными товарами без плана миграции и бездоказательное объявление категории опубликованной.

Каждую итерацию проводи по циклу: требования → реальная реализация → schema/migration/API contract → unit/integration/security tests → Playwright MCP в работающем браузере → сравнение с оригинальным Stitch, desktop/tablet/mobile → исправление → три независимых прогона после последнего изменения → обновление risk/acceptance/progress. Не подменяй реальный backend моками в E2E, не отключай тесты, не меняй baseline без разрешения. Работай безопасно в изолированном staging на тестовых данных. Не выполняй prod deploy, irreversible destructive actions и финансовые операции без разрешения.

Если нужный внешний IdP/KYC/платёжный/логистический сервис отсутствует, документируй `BLOCKED` и продолжай независимые задачи. Не заявляй PASS при невыполненных проверках. Заканчивай итерацию только с реальными доказательствами; затем переходи к следующей незавершённой задаче. Если сессия ограничена, запиши точный прогресс и способ возобновления.

Веди `docs/automation/ADMIN_PROGRESS.md` и отчёт `docs/qa/ADMIN_IMPLEMENTATION_REPORT.md`; укажи требование ID, commit SHA, исправления, затронутые файлы, API diff, миграции, результаты браузера, visual diffs, негативные проверки RBAC, последние три независимых прогона, незакрытые риски и следующую задачу. **Начни вносить код, а не только описывать план.**
